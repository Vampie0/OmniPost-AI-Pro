## System Overview

This repository uses **pnpm workspaces** as the primary dependency management system, orchestrated by **Turborepo** for build/dev/lint task execution across a monorepo containing two applications (`apps/admin`, `apps/mobile`) and two shared packages (`packages/tokens`, `packages/types`). The root `package.json` declares the workspace scope via `workspaces: ["apps/*", "packages/*"]` and pins the package manager version through `packageManager: "pnpm@9.0.0"`, ensuring all contributors use the same pnpm version.

## Key Files

- `package.json` (root) — workspace declaration, top-level scripts (`build`, `dev`, `lint`, `clean`), and pinned `packageManager` field.
- `pnpm-workspace.yaml` — workspace member patterns (`apps/*`, `packages/*`).
- `turbo.json` — task pipeline defining `build` (with `^build` cross-package dependency ordering), `lint`, and `dev` (persistent, uncached).
- `.npmrc` — pnpm configuration: `node-linker=hoisted`, `shamefully-hoist=true`, `auto-install-peers=true`, `strict-peer-dependencies=false`.
- `pnpm-lock.yaml` — lockfile generated by pnpm (present at repo root).
- `apps/admin/package.json` — Next.js admin app dependencies; references internal packages via `workspace:*` protocol.
- `apps/mobile/package.json` — Expo/React Native mobile app dependencies; also consumes `@socialpilot/tokens` and `@socialpilot/types` via `workspace:*`.
- `packages/tokens/package.json` — shared design tokens package, published under `@socialpilot/tokens`.
- `packages/types/package.json` — shared TypeScript types package, published under `@socialpilot/types`.

## Architecture & Conventions

1. **Workspace Packages**: Internal shared code is organized as npm-scoped packages under `packages/` (`@socialpilot/tokens`, `@socialpilot/types`). Applications consume them using the `workspace:*` protocol in their `dependencies`, enabling local development without publishing.
2. **Hoisted Layout**: The `.npmrc` configures pnpm to use a hoisted node_modules layout (`node-linker=hoisted`, `shamefully-hoist=true`), which flattens dependencies into a single `node_modules` tree rather than per-package isolation. This eases tooling compatibility but reduces strictness.
3. **Peer Dependency Handling**: `auto-install-peers=true` and `strict-peer-dependencies=false` allow pnpm to auto-resolve peer dependencies and relax peer mismatches, reducing friction during development.
4. **Task Orchestration**: Turborepo defines a `build` pipeline that depends on `^build` (upstream package builds run first), and caches outputs under `.next/**` and `dist/**`. The `dev` task is marked persistent and uncached for live-reload scenarios.
5. **Lockfile Strategy**: A single `pnpm-lock.yaml` at the repository root locks versions for all workspace members, providing deterministic installs across apps and packages.
6. **No Private Registry**: No `.npmrc` registry overrides or private auth tokens are configured; dependencies are resolved from the public npm registry.
7. **No Vendoring**: Dependencies are not vendored; they are installed via pnpm into `node_modules` directories per workspace member.
8. **Supabase Edge Functions**: The `supabase/functions/` directory contains Deno-based edge functions (`generate-content`, `generate-image`) that are part of the Supabase project and are not managed by pnpm.

## Conventions & Constraints

- All workspace members must declare themselves as `private: true` (observed in `apps/admin`, `apps/mobile`, and root); shared packages are intended for internal consumption only.
- Internal package references must use the `workspace:*` protocol (e.g., `"@socialpilot/tokens": "workspace:*"`) rather than version ranges, ensuring local development resolves to the workspace copy.
- Top-level scripts delegate to Turborepo (`turbo run build|dev|lint|clean`), so adding new tasks should be added to `turbo.json` pipeline entries rather than root scripts.
- The `packageManager` field pins pnpm to `9.0.0`; contributors are expected to use this exact version via Corepack or manual installation.
- Build artifacts are cached under `.next/**` and `dist/**` by Turborepo; new packages producing outputs should add matching output globs to the relevant pipeline entry.
